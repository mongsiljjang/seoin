# 서버를 만든다 — 무엇을, 어디에, 어떤 순서로

2026-10-06. 지금까지 "서버가 있어야 한다"고 미뤄둔 것들을 한자리에 모으고,
어디에 어떻게 만들지 정한 문서다.

## 0. 왜 지금인가

하루 동안 서버 없이는 안 되는 것이 네 개 나왔다.

| 하고 싶은 것 | 왜 서버가 필요한가 |
|---|---|
| 카카오 로그인 | Firebase 가 카카오를 모른다. 카카오가 준 신분증을 Firebase 가 믿는 형태로 바꿔줄 중간 역할이 필요하다 |
| 알림톡·문자 | 보내는 열쇠를 브라우저에 두면 아무나 그 열쇠로 문자를 보낸다 |
| 이메일 | 같은 이유 |
| 자동결제 | 정기결제 빌링키는 브라우저에 두면 절대 안 되는 값이다 |

공통점은 하나다 — **브라우저에 두면 안 되는 비밀값을 누군가 대신 들고 있어야 한다.**
그게 서버다.

## 1. 어디에 만드나

| | 돈 | Firebase 요금제 | 비고 |
|---|---|---|---|
| **Vercel 함수** | 무료 범위로 시작 | **무료(Spark) 그대로** | 이미 계정이 있다 |
| Firebase Cloud Functions | 무료 범위 있음 | **종량제(Blaze) 전환 — 카드 등록** | Firestore 와 한 몸 |

**Vercel 을 권한다.** 카드를 안 꽂아도 되고, 계정이 이미 있다.
Firebase 는 무료 요금제를 그대로 두고, 서버만 밖에 두는 구조다.

> 앱 배포는 **GitHub Pages 그대로** 둔다. Vercel 은 앱이 아니라 **서버 함수만** 올린다.
> 주소가 둘이 되면 승인이 둘이 된다 — 오늘 겪은 그 문제다.

## 2. 순서

### 1단계 · 카카오 로그인  ← 가장 큰 효과

오늘 하루를 통째로 잡아먹은 문제가 이것으로 풀린다.
**신분증이 기기가 아니라 계정이 되면**, 폰을 바꾸든 저장이 날아가든 같은 사람으로 들어온다.
승인은 사라지지 않고 **사람당 한 번**으로 줄어든다.

서버가 하는 일은 딱 한 가지다 — 카카오가 "이 사람 맞다"고 하면,
Firebase 가 알아듣는 표를 하나 끊어준다.

### 2단계 · 알림톡 / 문자

- 직원이 사용 요청을 내면 실장에게 알림톡
- 재고가 최소에 닿으면 담당자에게 알림톡
- 승인 코드 발송

알림톡은 카카오 비즈니스 채널과 발신 프로필이 있어야 하고 **심사가 있다.**
심사 전에는 문자로 보낸다.

### 3단계 · 이메일

사직서 사본, 월 보고서처럼 기록으로 남겨야 하는 것.
급한 알림은 알림톡이 낫다 — 병원에서 메일함을 보는 사람은 거의 없다.

### 4단계 · 자동결제

구조는 이미 잡아뒀다(`docs/OPERATOR_CONSOLE.md` 5장).
결제사가 `paidUntil` 을 미루기만 하면 앱과 규칙은 한 줄도 안 고친다.
병원 수가 적을 때는 수동이 오히려 편하니 제일 뒤에 둔다.

## 3. 몽실쌤이 준비해야 하는 것

코드는 내가 쓰지만, 계정과 열쇠는 주인만 만들 수 있다.

**1단계(카카오 로그인)에 필요한 것**

1. **카카오 디벨로퍼스** 앱 등록 → REST API 키
2. 그 앱에 **사이트 도메인** 등록 (`https://mongsiljjang.github.io`)
3. **Firebase 서비스 계정 키** 발급
   (콘솔 → 프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성)
4. 위 둘을 **Vercel 환경변수**에 넣기

**2단계(알림톡)에 필요한 것**

5. 카카오 비즈니스 채널 개설 + 발신 프로필 등록 (심사 기간 있음)
6. 문자 발송 업체 계약 (알림톡 심사 전 대체 수단)

## 4. 정직하게 짚어둘 것

**서버가 생기면 관리 책임이 생긴다.** 지금까지는 비밀값이 아예 없었다 —
보안규칙 하나가 전부였고, 그래서 털릴 것도 없었다.
서버가 생기는 순간 **서비스 계정 키와 결제 열쇠를 들고 있게 된다.**
그 열쇠가 새면 병원 전체가 열린다.

그래서 서버는 **쓰는 만큼만** 만든다. 기능을 서버로 옮기지 않는다 —
브라우저에 둘 수 없는 값만 서버가 들고, 나머지는 지금처럼 앱과 규칙이 한다.

**서버는 공짜가 아니다.** 지금은 고장 나도 내 브라우저만 멈춘다.
서버가 생기면 고장이 전 병원에 동시에 간다. 로그와 되돌리기를 같이 만들어야 한다.

## 5. 서버 없이 되는 길도 남아 있다

로그인 문제만 놓고 보면 **전화번호 문자 인증**으로도 같은 효과가 난다.
Firebase 가 기본으로 지원해서 **서버가 필요 없고, 무료 요금제 그대로**다.
이 앱은 이미 직원을 전화번호로 구분하고 있어서 잘 맞는다.
드는 돈은 문자값뿐이고, 직원이 한 번씩만 받는다.

**카카오 로그인이 꼭 필요한 이유가 "익숙함" 하나라면**, 문자 인증으로 먼저 가보고
불편하면 그때 카카오를 붙이는 쪽이 싸다. 서버는 2단계(알림톡)부터 만들어도 늦지 않다.


## 6. 사진 판독(LLM) — 2026-10-07 추산·결정

**결정: 지금은 만들지 않는다. 필요한 요구가 병원에서 나오면 그때 만든다.** 통화록 1-8장에서 실장이 그린 그림(수기 병원은
수첩을 하루 한 장 사진으로 올린다)이 이 앱에서 LLM 이 필요한 **유일한** 자리다. 폐기가 아니라 보류다
(2026-08-21 핸드오프). 용어집·노무 질의에 LLM 을 붙이는 것은 하지 않는다 — 틀리면 병원에 잘못된 안내가 나가고,
이 앱은 "판정하지 않고 점검표로 빠진 것을 찾아 준다"는 선을 지킨다.

**구조**: 앱 → (로그인 확인) → 버셀 서버 함수(API 키 보관) → 모델 → 결과를 지금의 **확인 표**로 넘긴다.
키를 브라우저에 넣지 않는다. 사진은 읽은 뒤 즉시 버리고 저장하지 않는다(환자 실명이 찍힌다 → 파일 저장소·카드 등록 불필요).
확인 표를 거치기 전에는 재고에 반영하지 않는다.

**병원별 하루 한도(제안)**: 기본 **5장/일**. 한도 칸은 계량기 설계(`license.maxScanPerDay`, 제작자만 정한다)에 이미 있다.
넘으면 수첩 텍스트 붙여넣기(항상 무료)로 안내한다. 별도로 제작자 계정에 월 지출 상한을 건다.

**비용 추산** — 가정: 사진 1장 입력 3,000토큰·출력 600토큰(생각이 항상 켜지는 모델은 출력 1,500토큰), 1달러 = 1,400원,
요금은 2026-10-07 공식 요금표. **토큰 수는 실제 사진으로 재야 한다(미측정).**

| 모델 | 요금(입력/출력 $/100만 토큰) | 1장 | 병원 1곳 월 110장(5장×22일) |
|---|---|---|---|
| Gemini 2.5 Flash-Lite | 0.10 / 0.40 | 약 0.8원 | 약 80원 |
| GPT-5 nano | 0.05 / 0.40 | 약 0.5원 | 약 60원 |
| Gemini 2.5 Flash | 0.30 / 2.50 | 약 3.4원 | 약 370원 |
| GPT-5 mini | 0.25 / 2.00 | 약 2.7원 | 약 300원 |
| Claude Haiku 4.5 | 1 / 5 | 약 8원 | 약 920원 |
| Claude Sonnet 5.5 | 2 / 10 | 약 29원 | 약 3,230원 |

| 네이버 클로바 OCR(검색 기준, 확인 필요) | 건당 50원 안팎 | 약 50원 | 약 5,500원 |

- 돈 차이는 병원당 월 수천 원 안이라 **가격이 아니라 손글씨 정확도가 기준**이다. 다시 찍는 경우는 ×1.5 로 본다
- 글자 인식(OCR) 전용 서비스는 글자만 뽑으므로 그 결과를 지금의 수첩 읽기 코드(`noteParse`)에 넣는 구조가 된다. 한글 손글씨 정확도는 미확인
  (흘림체는 인쇄체보다 오류율이 최대 3배라는 연구 요약이 있다)
- **개인정보**: 어느 회사든 입력 사진의 보관·학습 정책을 유료(API) 약관으로 확인해야 한다. 무료 등급 약관은 다를 수 있어 병원 자료에는 쓰지 않는다. 확인 못 했다
- **고정비**: 병원에서 돈을 받기 시작하면 버셀 무료 플랜(비상업 한정)이 안 맞아 유료 플랜이 필요하다(병원 수와 무관)
- **한 회사에 묶이지 않게** 모델 호출을 한 군데로 모아 만든다

**시험 계획(미실시)**: 환자 이름을 가린 수첩 사진 15~20장으로 후보 3~4개를 같은 조건에 읽혀 줄별 오독 수를 센다.
API 키와 호출 비용이 드니 시작 전에 사용자 승인을 받는다. 샘플 사진은 병원에서 받아야 한다.
