# LABOR_RULES.md — 노무 기능이 근거로 삼는 법령

MediOps 의 노무 화면(공지·근로계약서·급여명세서·사직서·직원 1페이지)이 **왜 그렇게 생겼는지**를 적어 둔 문서다. 화면의 어떤 칸이 어떤 조문에서 나왔는지 짝지어, 나중에 누가 봐도 이유를 알 수 있게 한다.

- 확인일: **2026-08-18**
- 확인 방법: 아래 출처를 웹에서 직접 읽고 정리
- **이 문서는 법률 자문이 아니다.** 서식과 운영은 배포 전 노무사 검토를 받는다. 병원 사정(교대·수습·포괄임금 여부)에 따라 필요한 항목이 달라진다.

---

## 1. 근로계약서 — 근로기준법 §17

사용자는 근로계약을 맺을 때 근로조건을 명시해야 하고, 그중 핵심은 **서면으로 만들어 근로자에게 교부**해야 한다.

**서면 교부 대상 (앱의 근로계약서 화면이 받는 칸)**

| 조문이 요구하는 것 | 앱의 입력 칸 |
|---|---|
| 임금의 구성항목 | 기본급 · 그 밖의 임금 구성항목 |
| 임금의 계산방법 | 계산 방법 |
| 임금의 지급방법 | 임금 지급일 · 지급 방법 |
| 소정근로시간 | 소정근로시간 · 근무일 |
| 주휴일 (§55) | 주휴일 |
| 연차유급휴가 (§60) | 연차유급휴가 |

**위반 시** — §114 에 따라 **500만원 이하 벌금**. 과태료가 아니라 **형사처벌**이다. 아르바이트·5인 미만 사업장·하루짜리 일용직도 예외가 아니고, **작성만 하고 근로자에게 건네지 않아도 위반**이다.

**앱이 하는 일** — 본문을 급여 열쇠로 잠가 저장하고, 직원이 대면으로 읽고 자기 PIN 을 눌러 확인한 시각을 남긴다. 교부 자체는 `🖨 인쇄해서 교부` 로 종이 한 장을 건네는 것으로 채운다.

## 2. 급여명세서 — 근로기준법 §48②

2021년 11월 19일부터 사용자는 **임금을 지급할 때마다 임금명세서를 교부**해야 한다.

**필수 기재사항 (앱의 §48② 경고가 검사하는 것)**

| 조문이 요구하는 것 | 앱의 검사 |
|---|---|
| 근로자를 특정할 수 있는 정보 | 성명 열을 못 찾으면 아예 안 읽는다 |
| 임금 총액 | `총액·합계·실지급·차인지급` 열이 없으면 경고 |
| 임금의 구성항목별 금액 | 지급 항목 열이 2개 미만이면 경고 |
| 출근일수·근로시간에 따라 달라지는 항목의 계산방법 | `연장·야간·휴일·초과·가산` 열이 있는데 `시간·시급·단가·일수` 열이 없으면 경고 |
| 공제 항목별 금액과 총액 | `공제·국민연금·건강보험·장기요양·고용보험·소득세` 열이 없으면 경고 |

**위반 시** — **500만원 이하 과태료**. 교부하지 않은 경우뿐 아니라 **기재사항 일부를 빠뜨리거나 사실과 다르게 적어 교부해도** 대상이다. 시행령 [별표7] 기준은 미교부 1차 30만원 · 2차 50만원 · 3차 100만원.

**앱이 하는 일** — 세무사·급여프로그램이 뽑은 엑셀을 그대로 읽어 직원별로 쪼갠다. 금액은 급여 열쇠로 잠가 저장하고, 화면에는 **한 번에 한 사람만** 띄운다. 교부 기록(누구·몇 월분·언제)은 잠그지 않는다 — 그게 의무 이행의 증거이기 때문이다.

## 3. 사직서 — 민법 §660②③

고용기간의 약정이 없는 경우, **상대방이 해지 통고를 받은 날부터 1월이 지나면** 해지의 효력이 생긴다(§660②). 사용자가 사직서를 수리하지 않아도 마찬가지다.

**월급제 근로자**는 §660③ 에 따라 **사직 의사표시를 한 당기(그 달) 후의 1기(다음 달)가 지나야** 효력이 생긴다.

> 예 — 5월 15일 제출, 병원이 수리하지 않음 → 당기(5월) 후 1기(6월)가 지난 **7월 1일**에 퇴직 효력 발생

**앱이 하는 일** — 그래서 중요한 건 **제출한 시각**이다. 직원이 앱에서 제출하면 시각이 그대로 박히고, 위 규칙으로 계산한 효력 예상일을 함께 보여준다(`resignEffect()` — 제출월 +2 의 1일).

## 4. 서류 보존 — 근로기준법 §42 · 시행령 §22

사용자는 근로자 명부와 근로계약에 관한 중요한 서류를 **3년간 보존**해야 한다. 기산점은 근로관계가 끝나거나 근로자가 퇴직한 날 등이다.

**대상** — 근로계약서, 임금대장, 고용·해고·퇴직에 관한 서류, 각종 서면 합의 서류(§51②, §51의2, §52, §53③, §55② 단서, §57, §58②③, §59①, §62), 연소자 증명 서류(§66).

**위반 시** — 500만원 이하 과태료.

**앱에서 유의할 점** — 직원을 **삭제**하면 기록이 같이 지워진다. 그래서 앱은 퇴사 처리(재직 상태 = 퇴사)를 권하고, 사직서 수리도 삭제가 아니라 퇴사 처리로 이어진다. **3년이 지나기 전에는 지우지 않는다.**

---

## 5. 연차 — 근로기준법 §60

이미 구현된 연차 자동 산정(입사일 기준)의 근거. 이번 노무 작업에서 새로 만든 것은 없고, 근로계약서의 `연차유급휴가` 칸이 이 조문을 가리킨다.

## 6. 앱이 다루지 않는 것 — 그리고 그 이유

| 안 만든 것 | 이유 |
|---|---|
| 4대보험 취득·상실 신고 | 주민번호가 필요하다. 고유식별정보라 암호화·접근기록 등 법정 안전조치 의무가 생기는데, 정적 웹앱에서는 지킬 수 없다 |
| 퇴직금 계산 | 평균임금 산정이 사안마다 다르고, 틀리면 임금체불이 된다 |
| 급여 자동 계산 | 4대보험 요율과 간이세액표가 매년 바뀐다. 틀리면 임금체불 |
| 앱 밖 알림(문자·카톡) | 서버가 필요하다. 상용화 Phase |

## 7. 알아둘 구조적 한계

**직원 PIN 이 공유 DB 에 평문으로 들어 있다** (`index.html` 의 `DB.staff[].pin`, 로그인은 내려받은 데이터와 클라이언트에서 대조). 앱 데이터 전체가 Firestore 문서 하나에 담겨 모든 기기로 내려가므로, 조금 아는 직원은 남의 PIN 을 읽을 수 있다.

그래서 급여와 근로계약서 본문은 **브라우저 안에서 AES-GCM 으로 잠근 뒤** DB 에 넣는다. 열쇠는 PBKDF2 로 만들고 어디에도 저장하지 않는다. 이건 잘 만든 잠금장치지 은행 수준 보안은 아니다.

**제대로 된 해법** — Firebase Auth 로 로그인을 바꾸고, 급여·계약서를 직원별 문서로 쪼갠 뒤 보안규칙으로 본인만 읽게 한다. PIN 평문 문제도 같이 풀린다. `docs/ROADMAP.md` 의 상용화 Phase 1순위.
