# 되돌리기 — 복구 지점과 절차

> 앱이 고장났을 때 어디로, 어떻게 돌아가는지. 급할 때 읽는 문서라 짧게 쓴다.

## 먼저 알아야 할 것 — 앱은 두 쪽이다

| 쪽 | 어디에 있나 | git이 되돌리나 |
|---|---|---|
| 화면·기능 (`index.html`) | GitHub Pages (`mediops-pilot` @ `main`) | **된다** |
| 보안규칙 (`firestore.rules`) | **Firebase 콘솔** (사람이 붙여넣어 게시) | **안 된다** |

**코드만 되돌리면 어긋남의 방향만 바뀐다.** 둘을 같은 시점으로 맞춰야 한다.

콘솔 규칙은 Firebase 콘솔 → Firestore Database → **규칙** 탭 → **기록(History)** 에서
게시했던 판을 골라 롤백할 수 있다. 게시본은 전부 보관된다.

## 8/19 판으로 되돌리기 — 실측으로 확인한 절차

### 반드시 둘 다 해야 한다

콘솔에 올라간 규칙은 옛 단일 문서에 **`allow write: if false`** 를 걸어 둔다.
8/19 판 앱은 그 문서 하나에 전부를 저장한다. 그래서 코드만 되돌리면
**앱은 열리고 PIN 로그인도 되지만 아무것도 저장되지 않는다.** 규칙 교체가 짝이다.

**① 코드** — 배포 저장소 `mediops-pilot` @ `main` 에서:

```bash
git checkout e6a07b3 -- index.html
git rm --cached firestore.rules && rm firestore.rules
git commit -m "8/19 판으로 되돌린다"
git push -u origin main
```

`e6a07b3` 은 `mediops-pilot` 에 없을 수 있다(백업본 `seoin` 의 커밋 번호다).
없으면 `seoin` 에서 파일을 꺼내 복사한다 — 내용은 같다.

**② 규칙** — `docs/rollback-0819.rules` 내용을
Firebase 콘솔 → Firestore Database → **규칙** 에 붙여넣고 **게시**.
(콘솔 **기록(History)** 에서 8/20 12:21 이전 판으로 롤백해도 된다.)

### 확인해 둔 것 — 안 건드려도 되는 것들

| 항목 | 결과 |
|---|---|
| `firebase-config.js` · `sw.js` · `manifest.webmanifest` | 8/19 이후 **바뀐 적 없음.** 그대로 두면 된다 |
| `WORKSPACE_ID` | `clinic` — 그때와 같은 문서를 본다 |
| 로그인 방식 | 두 판 모두 **익명 로그인**. 콘솔 인증 설정 건드릴 것 없다 |
| 서비스 워커 캐시 | `index.html` 은 **네트워크 우선**. 되돌리면 직원 폰에 바로 반영된다 |
| 되돌릴 파일 | `index.html` 하나 (318KB, 온전한 HTML로 확인) |

### 되돌린 뒤 예상되는 것

옛 앱은 `hospapp/clinic` 문서의 `db` 필드를 읽는다. 8/20 개편이 데이터를
하위 컬렉션으로 옮겼으므로 그 필드는 비어 있을 수 있다. 그러면 앱이
**이 기기에 남은 데이터로 다시 시작**한다(코드가 그렇게 되어 있다).
실제 운영 데이터가 없는 지금은 문제되지 않는다.

### 대가

8/19 판은 익명 로그인한 누구나 병원 데이터 전체를 내려받는다 — **PIN·급여 포함.**
8/20 개편이 막으려던 것이 정확히 이것이다. 되돌리는 것은 **실제 직원 데이터가
들어가기 전까지만** 유효한 선택이다.

## 데이터

앱 **설정 → 전체 백업(JSON)** 으로 파일로 빼고, **백업 파일 불러오기**로 되돌린다.
코드를 되돌려도 Firestore 안의 데이터는 그대로 남는다 — 되돌리기는 **코드만** 바꾼다.

## 되돌리기 전에 확인할 것

지금 나는 오류가 정말 코드 탓인가, 아니면 **콘솔 규칙이 뒤처져서**인가.
2026-08-20 기준 콘솔 규칙에는 앱이 쓰는 `meta` · `ownerkey` · `unlock` · `recovery`
네 경로가 없다. Firestore는 규칙에 없는 곳을 무조건 거절하므로,
이 경우 코드를 아무리 되돌려도 같은 종류의 오류가 계속 난다.
**규칙 게시가 먼저다.**
