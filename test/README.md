# 보안규칙 시험

`firestore.rules` 를 고치면 **반드시 여기를 돌린다.** 규칙은 이 앱의
유일한 보안 경계라서, 눈으로 읽고 넘어가면 남의 급여가 남에게 보인다.

## 돌리는 법

자바가 필요하다(에뮬레이터가 자바로 돈다). 두 개의 터미널을 쓴다.

```bash
cd test
npm install                 # 처음 한 번
cp ../firestore.rules .     # 고친 규칙을 가져온다
npm run emu                 # 터미널 1 — 에뮬레이터를 띄운 채 둔다
npm test                    # 터미널 2
```

`firestore.rules` 를 고칠 때마다 `cp` 를 다시 해야 한다.

## 무엇을 보는가

**`rules.권한.mjs`** — 누가 무엇을 볼 수 있는가 (52개)

- 예전 동작이 그대로인가 — 승인 안 된 기기·남의 급여·스스로 관리자 되기
- 개통 승인 — 설정이 꺼져 있으면 예전처럼, 켜면 승인받은 병원만
- 구독 기한 — 지나면 자료가 막히고, 그래도 남은 기간과 내 등록은 읽힌다
- 제작자 — 기한은 고치지만 **명단·PIN·급여·재고는 못 읽는다**
- 복구 코드 — 맞으면 들어오고 틀리면 못 들어온다
- 사직서 링크 — 한 번만 내고, 낸 사람도 못 읽고, 그 밖은 아무것도 못 본다

**`rules.한계.mjs`** — 규칙이 문서를 몇 개까지 들여다보는가 (11개)

Firestore 는 한 번 판단할 때 **문서 10개까지만** 조회할 수 있다. 넘으면
규칙이 터지고, 터진 규칙은 무조건 거절이라 **병원이 통째로 잠긴다.**
조건이 가장 많이 겹치는 상황(개통 승인 켜짐 + 병원 등록 + 구독 살아있음 +
복구 문 + 열쇠까지 전부 있는 상태)에서 개설과 읽기가 되는지 본다.

조건을 하나 더 얹을 때마다 이 파일을 먼저 늘리고 돌려본다.
