## 2. 결정과 근거

- **빠진 입력 확인은 판정이 아니라 할 일 알림이다.** AGENTS.md "화면에 내지 않는 것"에 맞춰: 홈에 안 내고, 빨간 숫자 없이, "오차"·"위반" 말투를 안 쓴다(시험이 말투를 지킨다). 기준 30일(`GAP_COUNT_DAYS`)은 내가 정한 값이다 — 사용자 확인 전.
- **지르코니아**: 사용자가 "커스텀 지르코니아 보험 된 지 오래됨"이라 짚었고, 다시 조사해 **지르코니아 크라운은 2025-02-01 진료분부터 급여**임을 확인해 안내를 고쳤다("PFM 외이면 시술 전체 비급여"는 낡은 문장). **맞춤형 지대주는 여전히 비급여로 안내되는 것까지만 확인**(공단 Q&A 2022-08, 2026-09 게시 안내자료) — 2025 개정이 지대주에 미쳤는지 고시 원문으로는 못 봤다. 화면에 "2022년 공단 Q&A 기준, 이후 바뀌었는지는 확인하지 못했어요"라고 달았다. 사용자: **"조사한 걸로 유지하자."**
- **65세 이상 조건은 화면에 안 넣었다** — 자료마다 갈린다(언론은 65세, 복지부 설명은 연령 언급 없음).
- **수첩 보험 단계 말과 `2차`는 다르다**: `1단계/2단계/3단계` = 보험 청구 단계(진단·고정체 식립·보철), `2차` = 2차 수술(힐링). 안내문에 구분을 적었다.
- **같은 환자 판단(`notePre`)**: 차트번호가 양쪽에 있으면 그것으로, 없으면 가린 이름 + (양쪽에 있으면) 생년월일 뒷 6자리 + 겹치는 치아. 여러 건이 걸리면 고르지 않고 새 케이스를 만든다(2차 수술 연결과 같은 방식).
- **케이스 목록 기간 필터**: 진단·1차·2차·보철 날짜 중 하나라도 기간 안이면 낸다(진단만 적힌 케이스가 사라지지 않게). 식립 **개수**는 1차 수술일 기준 — 목록과 숫자가 살짝 다를 수 있다(의도).
- **명세서 사진은 수첩 사진과 같은 서버 길**(`scanCall('bill', file)`)을 쓴다. 결과는 곧장 넣지 않고 기존 확인 화면(`previewPurchase`)을 거친다. PDF 는 아직 안 읽는다(이미지만).
- **의무교육 목록**(성희롱 예방·장애인 인식개선·개인정보·장애인학대 신고의무자·산업안전보건)은 이미 앱에 있다(`docs/EDUCATION_RULES.md`, 원문 대조). 사용자가 같은 교육들을 다시 언급했고 "있으면 괜찮다"고 했다. 직장 내 괴롭힘 예방교육은 법정 의무가 아니라 일부러 뺐다.
- **구글 독스는 사본이다**: 원본은 저장소의 `docs/GUIDE_최지원.md`. 앱이 바뀌어도 독스는 따라가지 않는다.

## 4. 검증 (마무리에서 다시 돌린 결과)

pilot·seoin 양쪽에서 시험 **19종 전부 0 실패**(보안규칙·`browser.*`·`_playwright` 제외). 늘어난 것: `입력빠짐` 13 · `대장기간` 11 · `명세서사진` 19 · `수첩읽기` 66(52→66). `deslop-ko`: **3개 항목 4곳 — 기준선과 같다, 새 지적 없음.** 보안규칙 시험은 `firestore.rules` 를 안 고쳐서 안 돌렸다.

### 안 본 것 (이 줄이 가장 비싸다)
- **실제 폰·화면에서 새 화면을 한 번도 안 눌러 봤다**: 빠진 입력 상자, 대장 기간 줄(◀ ▶ · 기간 · 전체), 거래명세서 사진·붙여넣기 화면, 수첩의 생년월일·단계 칸. 데모(`?demo=1`)도 이번엔 못 열었다(이 환경 브라우저가 로컬 파일을 못 열었다).
- **AI 호출을 한 번도 안 했다**(키 없음). `bill` 모드는 가짜 응답으로만 시험했고 실제 명세서 사진의 정확도는 모른다.
- 거래명세서의 **엑셀(.xlsx)·CSV 읽기**는 이번에 시험하지 않았다(기존 기능).
- 구글 독스: 변환 결과(표 머리글에 `**` 별표, 이모지 깨짐 여부)를 화면으로 못 봤다.
- 수첩 단계 줄을 **실서버(Firestore)에서** 저장·재읽기 해 보지 않았다(`d0`·`d3`·`birth` 필드).

### 사고 기록 (다시 겪지 않게)
- **셸 heredoc 으로 코드를 고치다 백슬래시가 사라져** 파일이 깨졌다(`join('\n')` 이 실제 줄바꿈이 됨). 이번에도 두 번 났다. **정규식·`\n` 이 든 수정은 `Edit`/`Write` 도구로 하거나 `Write` 로 만든 스크립트 파일로 한다.** 깨졌을 때는 `git checkout <파일>` 로 되돌리고 다시 했다.
- **줄바꿈 CRLF**: 작업 폴더의 파일은 CRLF 로 읽힌다. 여러 줄 문자열 치환은 읽을 때 `\r\n` → `\n` 으로 맞추고 쓸 때 되돌린다(`'\n' in s` 가 안 맞아 한 번 실패).
- **`*` 지우는 정규식이 규격 `4.0*10` 의 `*` 를 지웠다**(마크다운 별표 제거 중) → `` `|\*\* `` 로 한정했고 시험에 넣었다.
- **마무리 도중 Z:(병원 공유폴더) 연결이 끊겼다.** 셸 작업 디렉터리가 Z: 안에 있을 때 끊기면 Bash·PowerShell 이 출력 없이 `Exit code 1` 만 내고, Read·Write 도 실패한다(`EUNKNOWN`). GitHub 연결 도구로 대신 쓰려 했으나 **seoin 쓰기 403(권한 없음), pilot 은 404(비공개 접근 불가)** 였다. 연결이 돌아온 뒤 이 문서를 썼다. **이 PC 에서 이어 갈 때는 Z: 가 열리는지 먼저 본다.**
- 이전 사고(시험 실패한 채 푸시 등)는 앞 문서 참고.
