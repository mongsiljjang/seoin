## 3. 결정과 근거

**안내는 판정이 아니라 물음이다.** `docs/INSURANCE_RULES.md` 3장 그대로 옮겼다.
수가·개수·연령을 보지 않는다. 순서가 있다는 사실만 알린다 — 그래야 규정이 해마다
바뀌어도 이 문구가 틀리지 않는다. 기한 조건도 안 걸었다.

**새로 생긴 페일만 알린다.** 케이스를 고칠 때마다 뜨면 양치기가 되어 진짜 경고까지
묻힌다. `newFails(oldT, oldIns, newT, newIns)` 가 옛 페일과 대조해 새 것만 낸다.
일반→보험으로 바꾸면 옛 페일도 "처음 알리는 것"으로 본다 — 그때가 공단 등록이
처음 걸리는 시점이라서다.

**일반 페일은 덜 세지 않는다.** 사용자가 물어서 실측했다. 보험에만 붙은 것은
**안내 모달 하나뿐**이고, 재고 수량은 둘이 같은 코드를 탄다. 항등식
`매입 − 사용(일반+보험+페일) = 현재고` 가 다섯 경우 모두에서 성립하는 것을 확인했다.
심었다가 나중에 페일로 바뀌면 **구분만 옮겨가고 현재고는 안 움직인다** — 픽스처는
이미 나갔기 때문이다. 공단 등록 절차가 일반에는 아예 없어서 안내할 것이 없을 뿐이다.

**pilot 의 `README.md` 는 안 옮겼다.** 두 저장소의 README 는 서로 다른 문서다
(pilot 은 배포·파일럿 설명, seoin 은 사용자 안내). `AGENTS.md` 가 같게 두라고 한 것은
`index.html` 이다. `AGENTS.md` 자체는 공용 규칙서라 옮겼다.

## 7. 알아 둘 것 — 수첩 둘째 줄의 보험 구분

브라우저로 확인하다 본 것이라 적어 둔다. **결함인지 의도인지 사용자가 정해야 한다.**

```
08-19 홍길동 #46 보험 오스템 4.0×12 페일
#47 오스템 4.0×10                    ← 이름은 홍길동으로 이어지지만 구분은 '일반'
```

이름만 윗줄에서 이어지고 **보험 구분과 날짜는 안 이어진다.** 그래서 한 환자가
보험 케이스와 일반 케이스로 나뉘어 저장된다. 보험과 일반을 케이스 단위로 나눠
저장하는 것 자체는 심평원 실사 때문에 맞는 설계다(통화록 1-5장).

다만 실장이 "같은 환자니까 보험도 이어지겠지" 하고 적으면 조용히 일반으로 들어간다.
**확인 표에서 줄마다 보험/일반이 보이고 거기서 고칠 수 있어서** 저장 전에 잡히기는 한다.
그게 이 앱의 값어치("어디서 틀어졌는지 잡아내는")와도 맞는다. 그래서 이번에는 안 고쳤다.
