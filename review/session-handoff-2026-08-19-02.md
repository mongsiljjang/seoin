## 1. 세션 목표와 완료 결과

### 1단계 — 백업 (코드 완료 · 사용자 확인 대기)

내보내기는 원래 잘 돌았다. 실제 Chromium에서 확인: DB 항목 27개가 하나도 안 빠지고, **잠긴 급여·계약서도 암호문 그대로 들어간다**(열쇠만 기억하면 복구 후에도 열림).

문제는 **되돌리는 쪽**이었다. 백업은 복구가 돼야 백업이라, 여기를 고치지 않으면 2단계로 갈 수 없었다.

| 찾은 것 | 어떻게 터지나 |
|---|---|
| `{version, staff:[…]}` 만 맞으면 통과 | 남의 JSON 하나로 DB 전체가 두 줄이 되고, 그게 공유 서버로 밀려 **모든 기기에서 데이터가 사라짐**. 확인창도 없었음 |
| 불러온 뒤 `ensureSchema()` 미호출 | 노무 기능 전의 백업으로 되돌리면 배열이 없어 앱이 깨짐 |
| 복구 저장이 450ms 디바운스 | 그 사이 다른 기기 자료가 들어오면 복구가 조용히 없던 일이 됨 |

고친 것 — 아는 항목 3개 이상일 때만 진행 · 덮기 전 파일/현재 내용을 나란히 보여주고 확인 · 덮기 직전 상태를 기기에 남겨 **한 번 되돌리기** · 복구 후 `ensureSchema()` · 복구는 디바운스 없이 즉시(`cloudPushNow()`) · 내보낼 때 날짜 기록(`DB.lastBackupAt`) → 설정에 "마지막 백업" 표시 · **백업 파일에 직원 PIN과 잠긴 급여가 들었다는 보관 주의** 문구.

### wrap 스킬 수리

`/wrap` 인자로 "스킬 오류를 찾아 고쳐달라"는 요청을 받아 감사했다. 실제 결함 5건.

| # | 결함 | 근거 |
|---|---|---|
| 1 | `scripts/repo_snapshot.ps1` 이 **상대 경로** | 세션 작업 디렉터리는 프로젝트지 스킬 폴더가 아니다. `ls scripts/repo_snapshot.ps1` → 없음. 적힌 대로 실행하면 실패 |
| 2 | **Linux/macOS 판이 아예 없음** | 이 프로젝트는 Linux에서 돌고 PowerShell도 없다. 즉 스킬의 유일한 안전장치(`repository_count` 대조)가 실사용 환경에서 작동한 적이 없다 |
| 3 | **깨진 `.git` 을 정상 저장소로 보고** | `.git` 존재만 보고 판정해서, git이 부모 저장소로 거슬러 올라가 **부모 상태를 그 저장소 것인 양** 내놓는다. 재현: `broken/.git/HEAD` 에 쓰레기 → `head`·`status` 가 부모 것으로 채워짐(`?? ../deep/`) |
| 4 | git 실패를 `2>$null` 로 삼켜 **`clean:true` 로 둔갑** | 읽지 못한 저장소가 "깨끗함"으로 보고된다. 깨끗한 것과 모르는 것은 다르다 |
| 5 | SKILL.md가 **AGENTS.md와 충돌**하고, 요구사항 하나를 빠뜨림 | ①"Do not push"가 AGENTS.md의 "커밋 후 두 저장소 모두 푸시"와 정면 충돌 ②AGENTS.md는 "시작 프롬프트를 **채팅에** 코드블록으로 반드시 출력"인데 SKILL.md 보고 항목에 없고 오히려 "concise"로 민다 |

고친 것 — `scripts/repo_snapshot.sh` 신규(같은 JSON 출력) · 양쪽 스크립트에 `is_repo_root`/`Test-RepoRoot` 로 진짜 루트인지 확인 · 못 읽은 곳은 `unreadable_git_dirs` 로 드러냄 · `ok`/`error` 필드 추가하고 `clean` 은 `ok` 일 때만 참 · SKILL.md 절대경로·플랫폼 분기·출력 해석 지침 · "프로젝트 규칙이 이 기본값보다 우선" 명시 · 보고 항목에 시작 프롬프트 추가.

## 6. 열린 질문 · 리스크 · 미룬 일

- **[막고 있음] 사용자가 실제 백업을 아직 안 받았다.** 이게 1단계의 본체다. 앱 → 설정 → 💾 전체 백업(JSON) → 앱 밖 안전한 곳에 보관. **파일에 직원 PIN이 평문으로 들어 있으니 공용 PC 다운로드 폴더에 두면 안 된다**
- **[막고 있음] 백업 보강을 배포본에 반영할지 컨펌 안 남.** 데이터 구조는 안 건드리고 백업·복구 동작만 바뀐다
- **앞 세션 6장 리스크는 그대로 살아 있다** — 직원 PIN 평문(2~6단계가 해결) · 급여 열쇠 분실 시 복구 불가 · 퇴사자/신입 동명이인 · Storage 카드 보류 · 연차 차감이 병가까지 합산 · 사용자 실사용 확인 미완 · deslop-ko 잔여 3건 · 앱 안 외부 링크 2개 미확인
- **되돌리기는 기기 한 대에만, 한 번만 남는다.** `localStorage` 라 브라우저를 지우면 사라진다. 이건 파일 백업의 보조지 대체가 아니다
- **`unreadable_git_dirs` 는 발견만 하고 판단은 안 한다.** 사람이 봐야 한다
- **wrap 스크립트의 depth 한계는 그대로 뒀다.** 중첩 저장소 안의 중첩 저장소는 여전히 안 찾는다 — 원래 문서화된 설계라 바꾸지 않았다
