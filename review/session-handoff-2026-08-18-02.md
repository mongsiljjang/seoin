앞 핸드오프(`session-handoff-2026-08-18.md`)에 이어지는 세션. 이번 세션의 절반은 **재료 도메인 인터뷰**였고, 나머지가 구현이다. 인터뷰 결론이 곧 다음 작업 지시서라 6장을 반드시 읽고 시작한다.

## 1. 세션 목표와 완료 결과

일반 재고를 쓰기 쉽게 고치고, 치과 임플란트 재료 도메인을 인터뷰해 **임플란트 대장**을 새로 만들었다.

**재고 (일반)**
- **재고 세기**: 남은 개수만 세어 넣으면 지난 실사 이후 입고를 더해 사용량을 역산. 쓸 때마다 －출고를 누르지 않아도 된다
- **주문 텀·소진 예측**: 하루 평균 사용량 · 주문 시점 · 주문 텀 평균(입고 간격) · '주문임박' 필터
- **목록 압축**: 품목 카드(약 150px) → 한 줄(66px). 통계 블록 제거, 필터 칩에 개수, 검색창은 품목 8개 이하면 숨김
- **자주 쓰는 품목**: 계정별로 맨 위 고정(`DB.prefs[uid].pins`). 다른 직원 화면은 안 바뀐다
- **줄 메뉴**: 꾹 누르면(0.45초) 입고·출고·세기·자주·수정·삭제. 삭제는 관리자만(`delItem` 자체를 막음)

**임플란트 대장 (신규 · 재고 탭 → 📋 대장)**
- 한 줄 = 임플란트 하나 = 치아 하나. 치식도(FDI 32치)에서 골라 상악/하악 전체 버튼으로 전악 16~18개를 한 번에
- 같은 규격은 '선택한 치아에 적용'으로 일괄, LOT만 치아별로(스티커가 픽스처마다 한 장)
- 기록: 차트번호 · 환자 · 생년월일 · 보험/일반 · 픽스처 · LOT · 힐링 · 지대주(기성/커스텀) · 골이식재+병수 · 1차/2차 수술일 · 페일
- 환자 이름은 **성만 남기고 나머지는 초성**으로만 저장(김민수 → 김ㅁㅅ). 원본은 앱에 안 남는다
- **대장에 적으면 임플란트 재고가 준다.** 케이스를 고치면 바뀐 만큼만 반영(뺀 치아는 되돌림). 보험/일반/페일 구분이 따라간다
- **힐링 회수**: 2차 수술 때 나가 2주 뒤 인상채득 때 돌아온다. '나가 있는 힐링' 카드에 회수 예정일, 늦으면 빨갛게. 회수한 개수만 입력하면 나머지가 분실
- **재료 목록(⚙️)**: 픽스처(제조사·브랜드·사이즈)/어버트먼트/힐링/골이식/코핑. 순서 ▲▼, '안씀', CSV 저장·복구
- **거래명세서 올리기**: 엑셀·CSV를 올리면 브랜드·사이즈가 목록에 잡히고 입고까지. 명세서 자체는 `DB.purchases`에 남긴다(세무조사 대비)

## 2. 결정과 근거

- **새 재고 체계를 만들지 않고 수기 관리대장을 그대로 옮겼다.** 실장이 새로 배울 게 없고, 재고 차감·지대주 집계·보험 케이스가 그 한 줄에서 자동으로 나온다
- **진료기록은 담지 않는다.** 담는 순간 의료법상 진료기록부가 되어 보관 의무와 개인정보 부담이 생긴다. 덴트웹이 하는 일(인적사항·진료기록·청구 전송)은 만들지 않는다
- **환자 식별 = 차트번호 + 성+초성 + 생년월일.** 덴트웹이 초성 검색을 지원하므로 이름 원본 없이도 조회된다. 동명이인은 차트번호·생년월일로 가린다
- **코핑·아날로그 기공소 순환 관리는 만들지 않는다.** 커스텀이 대세라 기공소가 거의 다 쓰고 병원이 안 보낸다. 다만 아예 안 쓰는 건 아니라 목록·재고에는 남긴다(매입·사용·현재고·실재고만)
- **분실은 자동으로 잡지 않는다.** 수량이 안 맞을 때 관리자가 처리한다(기공소·환자에게 나가 있는 걸 잘못 털면 안 된다)
- **골이식재는 부위별.** 부위 넓이에 따라 병 수가 달라 치아 줄에 붙였다. 비급여라 보험 구분과 무관하게 센다
- **목록은 손으로 만들지 않는다.** 덴트웹식 수기 등록 대신 거래명세서·관리대장 업로드로 채운다
- **사진 자동 판독(OCR)은 미룬다.** 정적 앱에 API 키를 두면 누구나 꺼내 쓸 수 있어 서버가 필요하다. 당분간은 사진을 Claude 대화창에 보내 CSV로 변환하는 무료 경로를 쓴다

## 4. 검증 (실행 결과)

- **자주 쓰는 품목 계정 격리**: A가 2개 고정·순서 변경 → B로 로그인하면 원래 순서·별 0개 → A로 돌아오면 유지

## 6. 인터뷰 결과 — 다음 작업의 지시서

다음 세션은 이 장을 근거로 만든다. 재차 물을 필요 없다.

**재료 3분류 (미구현 · 최우선)**
사용자 표현 그대로 **일반재료 / 신고재료 / 임플란트재료**. 지금 앱은 일반 재고와 임플란트 둘뿐이라 신고재료가 없다.
- **신고재료** = 케타필·수술 실크 같은 **재료대 청구 품목**. 월 초에 구입 내역을 신고해야 하며 구입이 없어도 0으로 신고한다 → 월별 구입 내역 리포트가 필요 (신고처·양식은 아직 확인 못 함)

**담당자별 재고 구분**
임플란트 담당 / 물품·약품 담당 / **수술방 담당**(의약품·포도당·CGF). 수술방 재고는 숫자를 딱 맞추려는 게 아니라 **무단 사용을 양지로 끌어내려는 목적**이다. CGF가 가장 관리가 안 된다.

**거래대장 (미구현)**
거래처 담당자(영업사원)와 **같이 보고 내려받는** 장부. 패키지는 **금액 기준**(예: 1,000만원 걸고 까나감).
- 남은 패키지 잔액 · 새로 계약할 시점 · 새로 한 금액 · **최종 금액 = 남은 잔액 + 새 계약**

**재료 사용 대조표 (미구현 · 돈이 되는 기능)**
> 썼는데 차팅이 안 됐으면 돈도 안 받았다는 뜻

앱의 재료 사용 기록 ↔ 덴트웹 청구 내역을 맞추면 **차트 누락 = 미수금**이 잡힌다. 일주일 안에 잡으면 환자가 실밥 뽑으러 올 때 받을 수 있다.
- 덴트웹은 명세서를 **건별 조회·출력**만 확인됨. 목록 엑셀 내보내기 가능 여부는 **미확인** → 되면 자동 대조, 안 되면 앱이 대조표를 뽑고 사람이 눈으로 맞춘다

**힐링 어버트먼트 — 원장이 가장 보고 싶어 하는 것**
재활용하는데 분실이 매우 많고, 실장·원장 트러블의 원인. 정확할 필요는 없고 **오차 범위 가이드를 줄 정도**면 된다. 사이즈별로 유난히 많이 없어지는 게 있다. (회수 화면은 이번에 구현했고, 사이즈별 분실 통계는 미구현)

**흐름 정리**
1차 수술(픽스처·커버스크류) → 골유합(환자마다 다름) → **2차 수술(힐링 나감)** → 약 2주 → **인상채득(힐링 돌아옴)**

**보험**
어버트먼트는 기성·커스텀 **둘 다 재료 청구 대상**(커스텀도 급여화됨). 실사 때 **명세서(산 개수) = LOT 스티커(붙인 개수) = 환자 사용 개수(대장)** 세 개가 맞아야 한다. 재료 코드(허가번호) 칸은 불필요.

**브랜드**: 오스템 · 네오 · 디오 · 메가젠 + 기타(직접 입력)

**LOT 스티커**: 픽스처에 들어 있고 **한 개당 한 장**(같은 사이즈 3개면 3장). 한 장은 관리대장용, 한 장은 품질보증서용. 사진으로 보관하는 방향으로 합의 → Firebase Storage 필요

**아직 인터뷰 안 한 영역**: 서류 보관함(보험 명세서·기공 의뢰서·세금계산서·의약품 거래명세표), **노무**(사직서·근로계약서·급여명세서·공지 읽음확인·직원 1페이지), 요금제

## 7. 열린 질문 · 리스크

- **[버그] 재료 목록에 수량 칸이 없다.** 사용자가 손으로 항목을 추가하고 수량이 안 바뀐다고 보고. 목록은 제조사·브랜드·사이즈만 받고 수량은 임플란트 탭 ＋입고로만 들어간다. **목록에서 바로 수량을 넣을 수 있게 고쳐야 한다** — 다음 세션 1순위
- **파일 저장소 미결정.** Firebase Storage를 켜야 LOT 스티커 사진이 가능. 프로젝트 생성 시점에 따라 Blaze(카드 등록) 요구 가능 — 사용자가 콘솔에서 확인 예정. 예상 사용량은 연 160MB 수준으로 무료 한도 내
- **사용자 병원이 구강내과라 임플란트 케이스가 없다.** 대장을 실사용 검증할 수 없어, 사용자가 베타로 써보고 피드백하기로 함
- **관리대장 업로드 미구현.** 종이일 수도 사진일 수도 있음. 영업사원이 사진을 보내주는 흐름
- **덴트웹 청구 목록 엑셀 내보내기 가능 여부 미확인**
- **재료대 신고처·양식 미확인**
- **deslop-ko 잔여 3건**(모두 기존 코드): `.pill.grey`·`.hint` 저대비 4.3:1, `header.app` 색 있는 그림자, 본문 서체가 시스템 기본. 손대면 앱 전체 톤이 바뀌어 따로 정리할 때 한꺼번에 할 것
- **화면 사진 주의**: 사용자가 보낸 덴트웹 캡처에 환자 이름·주민번호 앞자리·상병코드가 있었다. 저장하지 않았고, 가리고 보내달라고 안내함
