## 2. 결정과 근거

- **보험 단계 점검은 판정이 아니라 알림이다.** 근거 조문과 경과 일수만 말하고 기한 위반이라 하지 않는다(단계 사이 청구 기한을 못 찾음). 수가 금액·급여/비급여 판정은 안 넣는다 — 단, **상병명·단계별 규칙은 마우스를 올리면 뜨는 안내로만** 넣기로 사용자가 정했다(`INSURANCE_RULES.md` 2장에 예외로 적음). 보철 안 들어옴 알림 기준 **90일**(`INS_PROS_WAIT_DAYS`)은 법이 아니라 알림 기준일이다.
- **개인정보**: 차트번호는 필수가 아니다(차트번호 **또는** 이름). 이름은 입력해도 **성과 끝 글자만 남고 가운데는 초성**으로 저장(원본 저장 안 함). 사용자 결정이고 이전 규칙(성만 남김)보다 이름이 더 드러난다 → `AGENTS.md` 에 예외로 적었다. 차트번호 없이 이름만이면 **생년월일이 둘 다 있어야** 같은 환자로 본다(가린 이름이 겹쳐 엉뚱한 알림이 나지 않게).
- **임플란트 탭 화면(사용자가 여러 번 고쳐 말했다 — 되돌리지 말 것)**: 회사 줄 맨 앞 `선택`이 기본. **선택일 때는 제품 이름 머리·재고 요약 없이 첫 제품의 규격 표만** 보인다(트리 없음). **회사를 누르면** 그 회사의 트리(부품 줄은 선택한 제품의 줄만 펼침)와 첫 제품의 규격 표(머리·요약 포함)가 보인다. 제품을 누르면 규격 표 자리로 스크롤. 부품 줄은 눌러서 접고 편다. 회사는 `DB.implants` 의 `brand` 글자로 묶는다(저장 구조는 그대로).
- **규격을 빼고 넣는 것은 병원마다 달라서 자유로워야 한다**: 규격 추가 창의 **삭제 = 그 칸 하나만**(등록 안 된 칸은 가리고, 등록된 규격은 지우되 숫자가 쌓였으면 한 번 묻는다). 두께 줄·길이 칸 전체는 머리글 숫자를 눌러 따로 뺀다(규격이 걸려 있으면 먼저 지우라고 안내만). 한 줄의 칸이 모두 가려지고 규격도 없으면 그 줄만 안 그린다.
- **사진 판독은 길을 여럿 열어 둔다**: 수첩 화면 맨 위 `✍️ 글로 붙여넣기 / 📷 사진으로 올리기`(고른 길은 기기에 기억). 글 쪽에는 폰의 글자 복사(텍스트 확대·렌즈)로 사진에서 글자를 뽑는 법 안내(i). **AI 서비스는 구글 Gemini·Anthropic Claude 둘 중**, 키는 ① 요청에 실린 **내 키(병원 키, 그 기기 localStorage 에만 — 서버 저장 안 함)** 먼저 ② 서버 환경변수. **사용자 결정: 구독제로 넘어갈 때는 운영자(사용자)가 키를 만든다 — 자세한 것은 나중에 의논.**
- **구글 무료 키는 이름이 보이는 사진에 쓰지 않는다**(무료 등급은 내용을 구글이 개선에 쓸 수 있고 사람이 읽을 수 있다 — 2024년 2차 자료 기준, 현재 약관은 ai.google.dev 에서 확인). 이름·차트번호가 보이는 운영은 유료 키. **사진은 AI 회사로 전송된다** 는 점을 화면에 적었다. 서버는 사진을 저장·로그하지 않는다.
- **LOT 는 촬영으로**: LOT 칸 옆 `📷`(규격 창·입고/사용 창·케이스 치아 줄). 순서 **바코드(GS1, AI 없이) → AI 라벨 모드 → 직접 적기**. 읽은 값은 눈으로 확인하라고 알린다.
- **서버를 옮기기 쉽게**: 사진 판독의 핵심은 `api/_core.js`(버셀과 무관, 계약 `handle({method,body,env}) → {status,json}`), `api/scan.js` 는 10줄 껍데기. 앱의 서버 주소는 `scanUrl()` 한 곳(`window.SCAN_API_BASE`).
- **DB 이전은 정해진 바 없다(클라우드도 미정).** 비용이 커지지 않게 **지도와 방어 장치만** 넣었다: `docs/DB_MIGRATION.md`(접촉면 43개 함수·데이터 지도·권한 표·Firebase 전용 기능·이전 순서·클라우드 선택 변수) · `test/DB접촉면.mjs`(Firebase 호출이 정해 둔 43개 함수 밖으로 퍼지면 실패) · `AGENTS.md` 규칙. **저장소 추상화 계층·다른 DB 구현은 일부러 안 했다**(두 구현 유지 비용, 규칙 에뮬레이터 시험 환경 없음).
- **병원 PC 의 작업 위치는 Z:**(앞 문서). 집에서는 Z: 가 안 열려 GitHub 사본을 쓴다 — 둘을 잇는 것은 GitHub 뿐이라 **마무리는 항상 푸시까지 하고, 다른 컴퓨터에서 이어갈 수 있게 한다**(사용자 요청 2026-10-12).

### 안 본 것 (이 줄이 가장 비싸다)
- **실제 폰에서 아무것도 안 봤다.** 급여 열쇠 새 화면·교육 일지 인쇄·이번에 만든 화면 전부.

- **실제 바코드 읽기를 안 했다.** `BarcodeDetector` 경로와 사파리용 `@zxing/library`(jsDelivr 에서 지연 로딩)는 실물로 시험 못 했다. **오스템·메가젠 박스의 바코드가 GS1 인지 모른다** → 샘플 사진이 필요하다.
- **실서버(Firestore)에 새 필드(`d0`·`d3`·`cellHide`·`axisHide…`)가 저장되고 다시 읽히는지** 안 봤다. 데모는 저장을 안 한다.
- 보안규칙 시험 6종·`browser.*` 2종은 안 돌렸다(`firestore.rules` 변경 없음, 이 PC 에 자바·playwright 없음).
- 이미 쌓인 보험 케이스에는 진단일(`d0`)이 없어 점검 상자에 "진단일이 비었어요"(ℹ️)가 많이 뜰 수 있다 — 확인이 필요한 것(⚠️)이 위로 정렬된다.

## 7. 다음 작업 (우선순위)

1. **사용자가 쓰다 불편한 곳이 있으면 그것 먼저.** 특히 폰에서 **급여 열쇠 정하기 → 복구 코드 → 급여 열쇠 권한**, **임플란트 탭(선택·회사·규격 삭제)**, **수첩 → 사진 올리기**, 케이스 입력 → 보험 단계 점검.
2. **샘플이 오면**: ① 덴트웹 엑셀 → **월말 대조 화면**(수첩 사용 개수 vs 덴트웹 월 개수, 월·규격·보험/일반/페일 합계, 환자 열은 버린다. 보험 쪽은 단계 건수로 — `INSURANCE_STEPS.md` 6장 "2단계 건수 ≈ 고정체, 3단계 건수 ≈ 지대주") ② 라벨 사진 → LOT 바코드 실검증·프롬프트 조정 ③ 수첩 사진 → 오독 수 세기(구글 vs Claude).
3. 입고·장부·남은 재고가 어긋나거나 입력이 빠진 것을 **체크**하는 화면(사용자 요청 — "입고 재고 장부상 현재고 실제 창고재고를 맞추고 입력 안 된 것이 체크되게"): 장부 식은 `이월 + 매입 + 교환입고 + 보정 − 사용 = 현재고` 로 이미 있고 남은 재고(직접 센 개수)와의 오차 표시도 있다. **빠진 입력을 알려 주는 점검**(입고 누락 등)은 아직 안 만들었다.
4. 엑셀 내보내기·가져오기에 보관 위치 열 · 의무교육 후속 · (이전이 정해지면) `DB_MIGRATION.md` 6장 순서.
