# Session Handoff — 2026-08-19 · MediOps

앞 핸드오프(`session-handoff-2026-08-18-02.md`)에 이어지는 세션. 재료 목록 버그를 고치고 **노무 도메인 전체**를 만들었다. 세션 후반은 "노무사 없는 병원"을 전제로 다시 쓰는 데 썼고, 마지막에 로그인 교체 계획을 잡았다.

## 1. 세션 목표와 완료 결과

**[버그] 재료 목록 수량** — 원인이 둘이었다.
1. 목록(마스터)은 제조사·브랜드·사이즈만 받고 수량은 재고(`DB.implants`)에만 있었다
2. `ensureSchema()` 의 주석 한 줄이 뒤에 붙은 코드 두 줄을 통째로 삼켜(`// 재료 목록…` 뒤 줄바꿈 누락) **`DB.implants` 초기화가 사라져 있었다.** 예전 버전에서 올라온 데이터는 목록을 재고에 등록할 때 그대로 터졌다

목록 한 줄마다 수량 칸을 넣고, 추가·수정 폼과 CSV 저장·복구에도 수량을 붙였다. 목록의 규격은 대장이 쓰는 것(`findVar`)과 같은 걸 찾으므로 대장에 적으면 그 수량이 그대로 준다.

**노무 (신규)** — 인터뷰 → 컨펌 → 구현 순서로 진행.

| 기능 | 자리 |
|---|---|
| 공지 · 읽음확인 | 홈 배너 + 직원 탭 → 공지 |
| 근로계약서 | 직원 탭 → 근로계약서 |
| 급여명세서 | 직원 탭 → 급여명세서 |
| 사직서 · 각종 신청서 | 직원 탭 → 서류 |
| 노무 점검 | 직원 탭 → 점검 (첫 화면) |
| 직원 1페이지 | 직원 탭 (직원으로 로그인하면) |

**권한 3단계** — 최고관리자(오너) · 인사담당자 · 직원. 예전 `관리자`가 그대로 오너라 로그인이 안 끊긴다. 인사담당자는 직원·출퇴근·연월차·노무를 보되 권한 변경·PIN 재설정·직원 삭제·재고 삭제는 못 한다.

**그 밖에** — 모달 ‹ 이전 버튼, 담당 분야(병원이 직접 추가), 거래처(이름·연락처·비고), 퇴사 처리 버튼과 복직, 전화번호 중복 허용(PIN은 달라야).

## 2. 결정과 근거

- **급여·계약서 본문은 브라우저에서 잠가 DB에 넣는다.** 앱 데이터 전체가 Firestore 문서 하나로 모든 기기에 내려가서, 화면에서 가리는 것만으로는 급여를 못 지킨다. PBKDF2 25만 회 + AES-GCM, 열쇠는 어디에도 저장하지 않고 3분 뒤 다시 잠근다. **잘 만든 잠금장치지 은행 수준은 아니다** — 제대로 된 해법은 로그인 교체다
- **금액은 한 번에 한 사람만 화면에 뜬다.** 짝짓기·목록·경고 어디에도 금액이 없다. 사용자가 "급여는 철저한 비밀유지"라고 지적한 데서 나온 규칙
- **5인 미만이면 연차가 법정 의무가 아니다 — 앱이 틀린 말을 하고 있었다.** 상시 4명 이하는 연차(제60조)와 연장·야간·휴일 가산수당(제56조)이 적용되지 않는데 모두에게 법정 연차를 계산해 주고 있었다. 치과는 5인 미만이 흔하다. `설정 → 우리 병원 직원 수` 를 받아 4명 이하면 '연차'를 **'휴가(병원이 정한)'** 로 부른다. 숫자와 기능은 그대로 뒀다 — 주기로 한 휴가도 근로조건이고, 이미 그렇게 써 온 기록을 앱이 지울 이유가 없다
- **법조문 기호를 화면에서 다 뺐다.** 사용자가 "(§60) 이게 무슨 의미인가?"라고 물은 게 결정적. 원장이 못 읽으면 실장도 직원도 못 읽는다. "근로기준법 제17조"로 풀어 쓰고, 본문은 평범한 말로 하고 조문은 작게 아래에 둔다
- **노무사 없는 병원을 전제로 쓴다.** "노무사 검토를 받으세요"로 넘긴 건 실무에서 아무도 안 하는 일이 된다. 앱은 **판단하지 않고 점검**하고, 막힐 때 갈 무료 창구(고용노동부 1350 등)를 앱 안에 둔다
- **최저임금 검사는 넣지 않는다.** 액수가 매년 바뀌어 앱에 박아두면 틀린 값으로 조용히 검사하게 되고, 치과위생사는 그 위에서 받아 선 자체가 의미 없다. **기준은 근로계약서에 적힌 금액**
- **진단서는 지금 앱에 올리지 않는다.** 건강정보(민감정보)라 별도 동의·안전조치 의무가 붙는다. 지금은 `서류를 종이로 받았어요` 체크만. **앱에 올리는 것을 최종 목표로 결정**했으므로 로그인 교체 뒤에 연다
- **Firebase Storage는 Blaze(카드)를 요구했고, 카드는 보류.** 로그인 교체를 먼저 하기로 했다

## 4. 검증 (실행 결과)

Playwright로 실제 Chromium에서 확인. **모든 시나리오 페이지 에러 0건.**

- **재료 목록**: `DB.implants` 를 지운 옛 데이터로 시작 → 오스템 TS III 4010 수량 30 등록 → 대장 2치아 기록 → 28로 차감. 힐링 40→38. CSV 복구 시 기존 항목은 수량만 갱신
- **잠금**: `JSON.stringify(DB.payslips).includes('2400000')` → `false`. 틀린 열쇠 → `null`. 열쇠 변경 시 기존 기록 재암호화(새 열쇠 열림·옛 열쇠 실패), 틀린 지금-열쇠는 아무것도 안 바꿈, 8자 미만 거부, 재설정 시 잠긴 기록 삭제 + 기록 남음
- **급여 매칭**: 전화·사번 자동 / 동명이인은 전화 뒷자리·부서·입사일로 질문(금액 노출 `false`) / 같은 값이 둘이면 안 붙임 / 한 사람 두 줄은 **버튼 잠김**
- **뒤바뀜 감지**: 두 사람 금액을 실제로 바꿔 넣어 확인. 처음 쓴 30% 임계값은 −22%/+29%라 **빠져나갔고**, 금액 일치 비교로 바꿔 둘 다 잡음. 계약서 기본급 대조는 **지난달 기록 0건 상태에서도** −8%/+9%로 잡음
- **권한**: 직원이 `withPayKey` 직접 호출 → 막힘. 인사담당자는 권한 선택칸·PIN칸·직원 삭제 버튼 없음, 재고·재료목록 삭제 차단. 마지막 최고관리자는 퇴사 처리 불가
- **5인 미만/이상**: 3명 → "병원이 정한 휴가", 8명 → "법으로 정해져 있어요". 직원 1페이지도 `남은 휴가` ↔ `남은 연차` 로 따라 바뀜
- **§ 기호**: 전 탭·전 서브탭 순회 후 화면에 남은 것 **0개**
- **서류**: 직원이 육아휴직 신청 → 관리자가 종이 접수 표시 → 승인. 관리자가 퇴사자 사직서 대신 등록(낸 날 7/15 → 효력일 9/1). 이미 쓴 유형은 삭제 차단
- **예전 데이터 마이그레이션**: 노무 필드를 전부 지우고 열어도 정상

## 6. 열린 질문 · 리스크 · 미룬 일

- **[1순위] 직원 PIN 이 공유 DB 에 평문으로 있다.** 조금 아는 직원은 남의 PIN 을 읽는다. 급여는 암호로 막아 뒀지만 근본 해법은 로그인 교체 → `docs/AUTH_MIGRATION.md`
- **급여 열쇠를 잊으면 아무도 못 연다.** 재설정은 잠긴 기록을 지운다(원본은 세무사·급여프로그램에 있음). 오너가 종이에 적어 보관해야 함
- **남은 구멍** — 퇴사자와 신입이 같은 이름이면 첫 달에는 계약서가 없는 한 못 잡을 수 있다. 사번을 넣으면 완전히 해결
- **Firebase Storage = Blaze 필요.** 카드 보류 중. 서류 파일 업로드·양식 파일 배포가 여기 걸려 있다
- **연차 차감이 병가·기타까지 포함한다.** `annualRemain` 이 승인된 모든 휴가의 일수를 합산한다. 병원 관행에 따라 의도일 수 있어 **건드리지 않았다** — 확인 필요
- **사용자가 아직 실사용 확인 안 함.** 특히 `설정 → 우리 병원 직원 수` 가 실제와 맞아야 그 아래 판단이 다 맞는다
- **deslop-ko 잔여 3건**(모두 기존 코드): `.pill.grey`·`.hint` 저대비 4.3:1, `header.app` 색 있는 그림자, 본문 서체가 시스템 기본. 손대면 앱 전체 톤이 바뀌어 따로 정리할 때 한꺼번에
- **앱 안의 외부 링크 2개**(`1350.moel.go.kr`, `law.go.kr`)를 이 환경에서 못 눌러봤다. 사용자가 "확인할 사람 없다"고 하여 그대로 둠
