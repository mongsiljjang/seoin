# baton — ChatGPT 판

Claude Code 판(`../SKILL.md`)과 **같은 원리, 다른 작동 방식**이다.

> ⚠️ **이 폴더의 파일은 Claude 스킬이 아니다.** `SKILL.md` 가 없어서 Claude 의 스킬 업로드 창에 넣으면 "유효하지 않은 스킬" 로 거부된다. 여기 것은 ChatGPT 에 **붙여넣고 업로드하는** 재료다. Claude 계정 스킬로 올릴 것은 `dist/baton-skill.zip` 이다(저장소 루트에서 `scripts/package.sh baton`).

## 왜 그대로 못 옮기나

Claude Code 판의 심장은 2단계 **실측**이다. 에이전트가 직접 `git status` 를 돌리고 검증을 다시 실행해, 기억이 아니라 실제 상태로 핸드오프를 쓴다.

**ChatGPT 는 그걸 못 한다.** 파일도 못 열고 명령도 못 돌린다. 그래서 그 자리를 이렇게 메웠다.

| | Claude Code | ChatGPT |
|---|---|---|
| 실측 | 에이전트가 직접 돌린다 | **사용자가 붙여넣는다** |
| 안 돌렸을 때 | 스스로 알고 적는다 | **GPT 가 먼저 요청하고, 없으면 "미확인"으로 적는다** |
| 가장 큰 위험 | 실측을 건너뛰기 | **없는 걸 확인했다고 지어내기** |

그래서 지침에 절대 규칙을 박아뒀다 — **받지 않은 것을 확인했다고 쓰지 않는다.** 지어내는 것보다 "미확인"이 백 배 낫다.

## 만드는 법 (커스텀 GPT)

1. ChatGPT → 왼쪽 **GPT 탐색** → **+ 만들기** → 위 탭에서 **구성(Configure)**
2. **이름**: `baton` · **설명**: `세션을 마무리해 다음 세션에 넘긴다`
3. **지침(Instructions)**: [`INSTRUCTIONS.md`](INSTRUCTIONS.md) 내용을 통째로 붙여넣기 (3,307자 — 한도 8,000자 안)
4. **지식(Knowledge)**: 아래 두 파일 업로드
   - [`../references/PRINCIPLES.md`](../references/PRINCIPLES.md) — 규칙이 어떤 실패에서 나왔는지
   - [`../references/TEMPLATE.md`](../references/TEMPLATE.md) — 서식과 자주 나오는 실수
5. **기능**: 웹 검색·이미지 생성·코드 인터프리터 **전부 꺼도 된다.** 이 GPT 는 글만 쓴다
6. **대화 스타터**: 아래 네 개를 넣는다

```
오늘 작업 마무리하고 다음 세션에 넘겨줘
핸드오프 써줘. 상태는 내가 붙여줄게
이 프로젝트 규칙부터 알려줄게
지난 핸드오프 이어서 쓸래
```

## 프로젝트 기능을 쓴다면

커스텀 GPT 대신 ChatGPT **프로젝트**의 지침란에 같은 내용을 넣어도 된다. 그러면 그 프로젝트 안 모든 대화에서 적용된다. 지식 파일은 프로젝트 파일로 올린다.

한 프로젝트만 쓴다면 이쪽이 편하고, 여러 작업에 두루 쓴다면 커스텀 GPT 가 낫다.

## 쓰는 법

마무리할 때 이렇게 부른다.

> 오늘 작업 마무리하고 다음 세션에 넘겨줘

GPT 가 상태를 붙여달라고 요청할 것이다. [`PASTE_COMMANDS.md`](PASTE_COMMANDS.md) 의 명령을 돌려 결과를 붙여넣는다. **이 단계를 건너뛰면 핸드오프의 절반이 "미확인"으로 나온다** — 그게 정상 동작이다. 거짓말하지 않는 것이다.

## 두 판을 같이 쓸 때

같은 프로젝트를 Claude Code 와 ChatGPT 로 오가며 작업한다면, 핸드오프 문서는 **한 곳에만** 둔다. 보통 저장소의 `review/` 다. 양쪽이 각자 문서를 만들기 시작하면 다음 세션이 뭘 믿어야 할지 모른다.
