# 마무리 — 다음 주자에게 넘긴다

`baton` 과 `wrap` 을 합친 것이다. 원본 둘은 그대로 있고 이것이 보완본이다.
바통을 바탕으로, 랩에만 있던 것과 **이 프로젝트에서 실제로 굳은 관습**을 얹었다.
프로젝트가 마무리 스킬을 하나만 가리켜야 사람이 안 헷갈린다.

## 이 스킬의 정체

**요약기가 아니다.** 이것을 놓치면 나머지가 전부 어긋난다.

| | 요약 | 핸드오프 |
|---|---|---|
| 향하는 곳 | 과거 | 다음 행동 |
| 읽고 난 뒤 | "아 그랬구나" | "지금 뭘 하면 되는구나" |
| 실패한 모습 | 길다 | **다음 세션이 이미 한 일을 또 한다** |

### 합격 기준은 하나뿐이다

> 대화 기록을 전부 지우고 이 문서만 읽었을 때, 다음 세션이 **첫 행동을 정확히** 할 수 있는가.

길이도 문체도 서식도 기준이 아니다. 문서를 다 쓴 뒤 이 질문을 스스로에게 던지고, 답이 "아니오"면 고쳐 쓴다.

### 순서

```
읽고  →  맞춰보고  →  남기고  →  넘긴다
RULES   RECONCILE    RECORD    HANDOFF
```

건너뛰고 싶은 유혹이 가장 큰 단계가 2번이고, 빠지면 가장 비싼 단계도 2번이다.

---

## 0. 시작 전

사용자가 다음 세션의 초점을 알려주면 그것으로 우선순위를 잡는다. **지금 작업의 범위를 넓히지 않는다** — 랩은 마무리지 새 작업이 아니다.

기획·브레인스토밍 플러그인은 사용자가 따로 요청하지 않는 한 쓰지 않는다.

---

## 1. 읽기 (RULES)

가장 가까운 `AGENTS.md` 또는 `CLAUDE.md` 를 읽는다. 이어서 README, 결정 로그, 기존 핸드오프·리뷰·계획·이슈·ADR 을 훑어 **이 프로젝트가 이미 쓰는 서식과 관습**을 파악한다.

- **서식은 프로젝트가 정한다. 내가 만들지 않는다.** 이미 쓰던 서식이 있으면 그걸 따른다.
- **프로젝트 규칙이 이 문서의 기본값을 이긴다.** 충돌하면 규칙을 따르고, 충돌했다는 사실을 핸드오프에 적는다.
- 프로젝트 규칙이 최종 보고에 무언가를 요구하면(예: 시작 프롬프트를 채팅에 출력) 그것도 4단계 보고에 포함한다.

---

## 2. 맞춰보기 (RECONCILE) — 건너뛰지 않는다

**대화 기억은 "내가 했다고 믿는 것"이고, 산출물은 "실제로 일어난 것"이다. 둘은 갈린다.** 기억만으로 쓴 핸드오프는 반드시 어딘가 틀리고, 그 틀린 곳이 다음 세션의 함정이 된다.

### 2-1. 산출물 상태를 실측한다

**git 저장소가 있으면** 이 스킬의 스냅샷 스크립트를 쓴다. 경로는 스킬이 호출될 때 주어진 base directory 기준이다 — **작업 디렉터리는 프로젝트지 스킬 폴더가 아니므로 상대 경로로 쓰지 않는다.**

- Linux · macOS: `<skill-dir>/scripts/repo_snapshot.sh <프로젝트경로> [최대깊이]`
- Windows: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <skill-dir>/scripts/repo_snapshot.ps1 -ProjectPath <프로젝트경로>`

둘 다 같은 JSON 을 낸다. **출력을 의심하며 읽는다.**

- `repository_count` 가 예상과 맞는가. 비었거나 모자란 스냅샷은 믿지 않는다
- `unreadable_git_dirs` 에 뭐가 있는가. 거기 항목은 `.git` 이 있지만 git 이 저장소 루트로 인정하지 않는 곳이다 — 손상되었거나 복사되다 만 체크아웃이다. 그 근처에서는 커밋하기 전에 원인을 밝힌다
- `ok: false` 는 **깨끗한 게 아니라 모르는 것**이다. `clean` 은 `ok` 가 참일 때만 의미가 있다
- 프로젝트 경로 **밖**의 저장소(디스크 다른 곳의 두 번째 체크아웃)는 발견되지 않는다. 따로 확인한다
- 스크립트는 프로젝트 아래 **세 단계**까지 훑고, 저장소를 찾으면 거기서 더 내려가지 않는다.
  최대 깊이는 작업공간 구조가 실제로 요구할 때만 올린다
- 스크립트가 안 돌면 수기로 확인한다 — 현재 브랜치·HEAD·스테이지된 변경·안 된 변경·최근 커밋·중첩 저장소

**git 저장소가 아니면** 산출물 종류에 맞게 같은 질문에 답한다.

| 산출물 | 실측할 것 |
|---|---|
| 글·원고 | 파일이 실제로 있는가, 어느 버전이 최신인가, 어디까지 썼는가(장·절 단위) |
| 디자인 | 시안 파일·링크가 열리는가, 어느 것이 채택본인가, 공유 설정은 |
| 데이터 분석 | 노트북이 처음부터 다시 도는가, 쓴 데이터셋의 버전·경로, 결과 파일이 있는가 |
| 문서·위키 | 저장됐는가, 누가 볼 수 있는가, 링크가 살아 있는가 |
| 외부 시스템 | 배포·발행·전송이 실제로 반영됐는가(대시보드나 URL 로 확인) |

각 저장소·산출물은 **독립적으로** 다룬다. 중첩 저장소를 실수로 gitlink 로 커밋하지 않는다. 무관한 사용자 변경을 보존하고, 히스토리를 절대 다시 쓰지 않는다.

### 2-2. 검증을 다시 돌린다

**"통과했다"고 쓰려면 지금 다시 돌린다.** 세션 중간의 통과는 그 시점의 사실이고, 그 뒤에 뭔가 바뀌었을 수 있다.

- 다시 돌렸으면 **실제 출력**을 근거로 쓴다. "테스트 통과" 말고 "15개 시나리오 통과, 에러 0건"
- **못 돌리면 그렇게 적는다** — "지난번 결과이고 이번엔 재확인 못 함". 이게 정직한 상태다
- **결과가 기억과 다르면 그 사실 자체가 가장 중요한 핸드오프 항목이다.** 조용히 고치고 넘어가지 않는다
- 검증한 것과 **안 한 것의 경계**를 적는다. "무엇을 확인했다"보다 "무엇은 안 봤다"가 다음 세션에 더 비싸다

### 2-3. 갈라진 것을 찾는다

같아야 할 두 곳이 갈라져 있으면 **반드시 적는다.** 두 저장소, 원본과 사본, 로컬과 배포본, 문서와 코드.

갈라짐 자체는 죄가 아니다 — 컨펌 대기 같은 정당한 이유가 있을 수 있다. **안 적는 것이 죄다.** 안 적으면 다음 세션이 사고로 오해하거나, 모르고 덮어쓴다.

## 3. 남기기 (RECORD)

### 수록 기준 — 되찾을 수 있는가

이 한 줄이 랩의 전부다.

| | 처리 | 왜 |
|---|---|---|
| **되찾을 수 있는 것**<br>커밋 메시지·diff·파일 내용·배포 URL·이슈 번호 | **링크·경로·SHA 만** | 옮겨 적으면 요약기가 되고, 곧 낡아서 거짓말이 된다 |
| **되찾을 수 없는 것** | **본문에 쓴다** | 여기 없으면 영영 사라진다 |

되찾을 수 없는 것은 이 여섯이다.

1. **왜 그렇게 정했나** — 산출물은 *무엇을* 담지 *왜*를 못 담는다
2. **뭘 시도했다 버렸나** — 안 적으면 다음 세션이 같은 삽질을 반복한다
3. **뭘 확인했고 뭘 안 했나** — 검증의 경계
4. **지금 막혀 있는 것과 그걸 풀 사람** — 나인지 사용자인지 외부인지
5. **건드리면 안 되는 것** — 지뢰밭 표시
6. **다음 순서**

### 답해야 할 아홉 가지

**이건 서식이 아니라 질문이다.** 서식은 프로젝트 관습을 따르고, 이 질문들에는 어떤 서식이든 답이 들어 있어야 한다. 질문이 고정이라 코드든 글이든 디자인이든 그대로 굴러간다.

1. 이번 세션의 목표와 실제로 끝낸 것
2. 내린 결정과 그 근거 (짧게, 그러나 근거 없이 결론만 적지 않는다)
3. 산출물과 그 위치 — 링크·경로 위주
4. 검증한 내용과 **정확한 결과** (2-2 에서 다시 돌린 것)
5. 산출물·저장소·배포 상태 (2-3 의 갈라짐 포함)
6. 열린 질문 · 위험 · 일부러 미룬 일
7. 다음 작업 (우선순위 순)
8. 다음 세션 추천 스킬 — **실제로 있는 스킬만**
9. 복사용 다음 세션 시작 프롬프트

### 어디에 쓰나

프로젝트에 관습이 있으면 따른다. 없으면 만든다.

`review/session-handoff-YYYY-MM-DD.md`

같은 날 이미 있으면 `-02` 처럼 접미사를 붙인다. 작업공간을 건드리면 안 되거나 프로젝트가 없으면 OS 임시 폴더에 쓴다.

**새 작업이 없으면 새 핸드오프를 만들지 않는다.** 상태만 확인해 보고한다. 빈 핸드오프는 다음 세션에게 소음이다.

지속적인 결정은 결정 로그에도 남긴다. README 의 진척도는 **완료를 실제로 확인했을 때만** 고친다.

### 지우고 쓴다

비밀번호·토큰·자격증명·개인 식별정보·불필요한 개인정보는 핸드오프에도 커밋에도 넣지 않는다. 산출물 안에 그런 게 들어 있는 걸 발견했으면 **그 사실 자체를 위험 항목으로 적는다**(값은 빼고).

## 4. 넘기기 (HANDOFF)

### 커밋

변경된 각 저장소마다:

1. 임시 로그·아카이브·자격증명·생성된 캐시를 지우거나 무시 목록에 넣는다
2. diff 와 추적되지 않는 파일을 **읽는다**
3. 이번 세션 작업만 스테이지한다
4. `git diff --cached --check`
5. **무엇이 달라졌는지**를 말하는 메시지로 커밋한다 — 무엇을 만졌는지가 아니라
6. 짧은 SHA 를 기록한다

푸시·배포·PR·공유 설정 변경은 사용자가 요청했거나, **프로젝트 규칙이 요구하거나**, 이미 지금 작업의 일부일 때만 한다. 1단계에서 읽은 규칙이 이 기본값보다 우선한다 — **매 세션 푸시로 끝내라는 프로젝트에서 이 기본값을 따르면 작업이 그대로 고립된다.**

### 확인

필요한 문서가 있는가, 커밋에 의도한 파일만 들었는가, 민감정보나 임시 패키지가 안 들어갔는가, 모든 저장소가 깨끗하거나 설명되는가.

### 보고

- 핸드오프 문서 경로
- 저장소별 커밋 SHA
- 배포·산출물 링크 (해당되면)
- **다음에 할 첫 행동**
- 추천 스킬
- 남은 미정리 파일이나 막힌 것
- **복사용 시작 프롬프트를 코드블록으로**

**시작 프롬프트는 채팅에 낸다. 문서 안에만 두지 않는다.** 사용자가 새 세션을 여는 그 순간에는 저장소를 열어볼 수 없다. 프로젝트 규칙이 최종 메시지에 더 요구하는 게 있으면 그것도 여기 넣는다.

나머지는 짧게 쓴다. 자세한 건 핸드오프 문서가 진다.

## 하지 말 것

- **완료를 부풀리지 않는다.** "했다"와 "확인했다"는 다르다. 미완과 미확인을 숨기면 다음 세션이 그 위에 쌓아 올려 더 비싸진다
- **기억으로 검증 결과를 쓰지 않는다.** 2-2 를 건너뛰면 랩이 오히려 틀린 사실을 굳혀준다
- **산출물에서 읽을 수 있는 걸 옮겨 적지 않는다.** 그 순간 요약기가 된다
- **범위를 넓히지 않는다.** 랩 중에 발견한 문제는 고치지 말고 6번 항목에 적는다 (지금 당장 위험한 게 아니라면)
- **없는 스킬을 추천하지 않는다**

---

## 프로젝트마다 관습이 다르다 — 스킬은 그걸 읽는다

**이 스킬에는 특정 프로젝트 이야기를 넣지 않는다.** 넣는 순간 다른 프로젝트에서
거짓말이 된다. 관습은 프로젝트 안에 있고, 스킬은 1단계에서 그것을 읽어 따른다.

### 어디를 보나

순서대로 찾고, 처음 찾은 것을 쓴다.

1. `AGENTS.md` · `CLAUDE.md` 의 **마무리·핸드오프 절**
2. `review/` · `docs/` 의 **가장 최근 핸드오프** — 실제로 쓰인 서식이 여기 있다
3. `README` · 결정 로그 · 기여 규칙

여기서 답을 얻어야 할 것들이다.

| 물음 | 없으면 |
|---|---|
| 산출물 저장소가 몇 개인가 | 스냅샷 결과를 믿는다 |
| 검증을 무엇으로 돌리나 (시험·린트·빌드 명령) | 저장소에서 찾는다. 못 찾으면 **안 돌렸다고 적는다** |
| 커밋 뒤 푸시까지 하나 | 안 한다 (4단계 기본값) |
| 핸드오프를 어디에 어떤 이름으로 두나 | `review/session-handoff-YYYY-MM-DD.md` |
| 최종 보고에 반드시 넣을 것이 있나 | 4단계 기본 보고 |
| 화면·문서에 **내면 안 되는 것**이 있나 | 비밀·개인정보만 거른다 |

### 관습이 안 적혀 있으면 — 이번에 적어 둔다

마무리하면서 **알아낸 것이 곧 그 프로젝트의 관습**이다. 시험 명령을 찾느라 헤맸다면
다음 세션도 헤맨다. 그러니 알아낸 것을 프로젝트 문서(`AGENTS.md` 의 마무리 절이
가장 좋다)에 짧게 적고, 적었다는 사실을 보고한다.

**한 번 겪은 사고는 반드시 적는다.** 잘못 푸시했다거나, 명령이 엉뚱한 저장소에서
돌았다거나, 되돌린 화면이 있다면 — 그 경위와 막는 법을 남긴다. 다음 세션은 그
사고를 안 겪었으므로 문서가 없으면 똑같이 밟는다.

이렇게 하면 프로젝트마다 자기 체크리스트가 쌓이고, **스킬은 하나로 유지된다.**
