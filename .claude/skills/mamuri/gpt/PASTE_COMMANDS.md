# 붙여넣을 것 모으기

ChatGPT 는 네 컴퓨터를 못 본다. 이 페이지의 결과를 붙여넣어야 핸드오프가 **사실**이 된다. 안 붙이면 GPT 는 그 항목을 "미확인"으로 적는다 — 고장이 아니라 정상이다.

## 코드 작업

터미널에서 프로젝트 폴더로 간 뒤 통째로 붙여넣는다.

```bash
echo "=== 브랜치 ===";  git branch --show-current
echo "=== HEAD ===";    git rev-parse --short HEAD
echo "=== 정리 안 된 것 ==="; git status --short
echo "=== 최근 커밋 ==="; git log --oneline -5
echo "=== 원격과 차이 ==="; git status -sb | head -1
```

**저장소가 여럿이면 각각 돌린다.** 하나만 보고 쓴 핸드오프는 나머지에 대해 거짓말을 한다.

### 검증 다시 돌리기

세션 중에 통과한 걸 **지금 다시** 돌린다. 프로젝트에 맞는 걸 골라 쓴다.

```bash
npm test          # 또는  pytest / go test ./... / cargo test
npm run lint
npm run build
```

결과를 그대로 붙인다. **실패해도 붙인다.** 실패를 숨기면 다음 세션이 그 위에 쌓는다.

돌릴 수 없는 상황이면 GPT 에게 **"이번엔 재확인 못 했다"**고 말한다. 그러면 그렇게 적힌다.

## 글·원고 작업

말로 답해도 된다.

- 원고 파일이 어디 있고, 어느 게 최신인가
- 어느 장·절까지 썼나
- 교정은 어디까지 봤나
- 다른 데(블로그·전자책 플랫폼)에 올린 게 있나, 최신인가

## 디자인 작업

- 시안 파일·링크가 어디 있나, 열리나
- 어느 게 채택본인가
- 공유 설정은 (링크 있는 사람만? 특정 인원만?)

## 분석 작업

```bash
ls -la 결과폴더/
```

- 노트북이 **처음부터 끝까지** 다시 도는가 (중간부터만 돌린 결과는 못 믿는다)
- 어느 데이터셋의 어느 버전을 썼나
- 결과 파일이 실제로 생겼나

## 어디서든 답해야 하는 세 가지

GPT 가 물을 것이고, 안 물어도 먼저 말하는 게 낫다.

1. **같아야 하는데 갈라진 곳이 있나** — 저장소 두 개, 원본과 사본, 로컬과 배포본. 갈라짐 자체는 문제가 아니다. **안 적는 게 문제다**
2. **막혀 있는 게 있나, 누가 풀어야 하나** — 나인지, GPT 인지, 남을 기다려야 하는지
3. **이번에 확인 못 한 게 뭔가** — 이게 다음 세션에 가장 비싼 정보다

## 비밀은 빼고 붙인다

붙여넣기 전에 훑어본다. API 키, 비밀번호, 토큰, 주민번호, 실명·연락처가 섞여 있으면 지우고 붙인다.

**대신 "그런 게 들어 있더라"는 사실은 GPT 에게 말한다.** 값은 빼고. 그러면 위험 항목으로 핸드오프에 남아 다음 세션이 조심한다.
