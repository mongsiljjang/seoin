# 기본 서식

**프로젝트에 이미 쓰는 서식이 있으면 그걸 따른다.** 이 파일은 관습이 없을 때만 쓴다.

각 절은 `SKILL.md` 의 아홉 가지 질문에 하나씩 대응한다. **답할 게 없는 절은 지운다** — 빈칸을 채우려고 없는 말을 지어내면 다음 세션이 그걸 믿는다.

각 절 아래 `>` 로 시작하는 줄은 쓰는 요령이고, 실제 문서에는 남기지 않는다.

---

```markdown
# Session Handoff — YYYY-MM-DD · <프로젝트>

<앞 핸드오프와의 관계 한 줄. 무엇을 이어받아 어디까지 갔는지.>

## 1. 세션 목표와 완료 결과

> 목표와 실제 결과를 나눠 쓴다. 목표를 못 채웠으면 그렇게 적는다.
> 여러 갈래로 일했으면 갈래별로 나눈다.

## 2. 결정과 근거

> 결론만 적지 않는다. 근거 없는 결정은 다음 세션에서 그대로 뒤집힌다.
> 특히 "안 하기로 한 것"과 그 이유를 적는다. 이게 없으면 다시 논의된다.
> - 결정 · 왜 · 무엇을 포기했는지

## 3. 산출물

> 링크·경로·SHA 위주. 내용을 옮겨 적지 않는다.
> 코드면 커밋, 글이면 파일과 버전, 디자인이면 시안 링크, 분석이면 노트북과 결과물.

## 4. 검증 (실행 결과)

> 랩 중에 다시 돌린 결과를 쓴다. 실제 출력 기준으로.
> **무엇을 안 봤는지도 여기 쓴다.** 이 줄이 가장 비싸다.
> 재확인 못 한 항목은 "지난번 결과이고 이번엔 재확인 못 함"이라고 밝힌다.

## 5. 산출물·저장소·배포 상태

> 저장소별 브랜치·HEAD·clean 여부. 배포본 반영 여부.
> **같아야 할 것이 갈라져 있으면 여기 적는다** — 무엇이, 왜, 언제 맞출 건지.
> 중첩 저장소나 읽지 못한 곳이 있으면 적는다.

## 6. 열린 질문 · 위험 · 미룬 일

> 막고 있는 것은 [막고 있음] 처럼 표시하고, **그걸 풀 사람이 누군지** 밝힌다.
> 앞 세션에서 넘어와 아직 살아 있는 위험도 다시 적는다 — 사라진 게 아니다.
> 랩 중에 발견했지만 고치지 않은 것도 여기.

## 7. 다음 작업 (우선순위)

> 순서대로. 1번은 다음 세션이 **바로 시작할 수 있을 만큼** 구체적으로.

## 8. 다음 세션 추천 스킬

> 실제로 설치돼 있는 것만. 실행 명령이 있으면 같이 적는다.

## 9. 다음 세션 시작 프롬프트 (복사용)

> 이 블록은 **채팅에도 그대로 낸다.** 문서 안에만 두면 쓸모가 절반이다.
> 담을 것: 프로젝트·저장소·브랜치 / 먼저 읽을 문서 / 이미 결론 난 것(다시 묻지 말 것)
> / 지금 막혀 있는 것 / 다음 할 일 / 지켜야 할 원칙

```
MediOps 치과 앱 이어서 작업. 정식본 ..., 백업 ..., 작업 브랜치 ...

시작 전에 AGENTS.md 와 review/session-handoff-YYYY-MM-DD.md 를 읽어줘.
N장과 M장이 지시서니까 이미 답이 나온 건 다시 묻지 마.

지금 막혀 있는 것: ...
다음 할 일: ...
원칙: ...
```
```

## 자주 나오는 실수

| 이렇게 쓰면 | 이렇게 고친다 |
|---|---|
| "버그를 수정했다" | "무엇이 어떻게 터졌고, 왜 그 방법으로 고쳤나" (증상 → 원인 → 선택) |
| "테스트 통과" | "몇 개 시나리오를 어떤 조건에서 돌려 무엇이 나왔나. 무엇은 안 봤나" |
| "리팩터링함" | diff 를 보면 안다. **왜** 그 구조를 골랐는지만 적는다 |
| "나중에 개선 필요" | 무엇을, 왜, 언제까지, 안 하면 뭐가 터지나 |
| "사용자와 논의 필요" | 무엇을 물어야 하는지 **질문 문장 그대로** 적는다 |
| 지난 위험을 안 옮김 | 해결 안 됐으면 매 핸드오프에 다시 적는다. 빠지면 없어진 걸로 읽힌다 |
