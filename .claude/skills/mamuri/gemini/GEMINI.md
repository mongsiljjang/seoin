# 마무리 (mamuri) — Gemini CLI 용

Gemini CLI 는 파일과 셸에 닿는다. 그래서 **Gem 판과 달리 네가 직접 실측한다.**
이 파일을 프로젝트 뿌리의 `GEMINI.md` 에 넣거나, 이미 있으면 아래 내용을 이어 붙인다.

사용자가 **"마무리"·"마무리하자"·"랩"·"핸드오프"·"다음 세션에 넘겨줘"** 라고 하면
아래를 따른다. 단순 요약 요청("지금까지 뭐 했는지 알려줘")에는 쓰지 않는다.

전체 절차는 같은 폴더의 `../SKILL.md` 에 있다. **그것을 읽고 그대로 따르되,**
Gemini CLI 에서 달라지는 것만 여기 적는다.

## 직접 돌린다

`../scripts/repo_snapshot.sh <프로젝트경로>` 로 저장소 상태를 실측한다.
스크립트가 안 돌면 손으로 확인한다 — 브랜치·HEAD·정리 안 된 것·최근 커밋·중첩 저장소.

**검증을 지금 다시 돌린다.** 세션 중의 통과는 그 시점의 사실이다.
돌린 명령과 **실제 출력 숫자**를 핸드오프에 적는다. 못 돌렸으면 못 돌렸다고 적는다.

## 커밋은 하되 푸시는 묻는다

프로젝트 규칙(`AGENTS.md`·`GEMINI.md`)이 매 세션 푸시를 요구하면 푸시한다.
그런 말이 없으면 커밋까지만 하고 푸시 여부를 사용자에게 묻는다.

## 저장소가 여럿이면 경로를 못 박는다

`cd` 로 옮겨 다니지 말고 **`git -C <경로>`** 를 쓴다.
복합 명령에서 `cd` 가 남아 엉뚱한 저장소에 푸시하는 사고가 실제로 있었다.

## 넘기기

핸드오프는 프로젝트 관습을 따라 파일로 쓴다. 관습이 없으면
`review/session-handoff-YYYY-MM-DD.md`. 같은 날 이미 있으면 `-02`.

**복사용 다음 세션 시작 프롬프트는 파일 안에만 두지 말고 화면에도 코드블록으로 낸다.**
사용자가 새 세션을 여는 순간에는 저장소를 열어볼 수 없다.
